Scoring rules and source
  • Source: supplied ft_transcendence.pdf, version 21.2. Modules: printed pp. 10–20; bonus: p. 30. PDF viewer pages are one higher.
  • Major = 2 points; minor = 1 point. Incomplete/non-functional modules earn zero. Required module threshold: 14 points. Bonus: at most 5 extra points, conditional on completing required work.
  • This is a self-assessment tool. Checked modules with missing tracked prerequisites are excluded from the eligible total. Evaluators decide final acceptance. This is not a final-grade calculator.
  • Conservative framework accounting: the combined major and the frontend/backend minors are alternative representations. Selecting one representation clears the other. The PDF lists all three but does not explicitly resolve stacking.
  • SSR and ICP are mutually exclusive; selecting one clears the other.
  • G01 represents the required functional game. Blockchain scores additionally require G07 here as a conservative practical prerequisite, not an explicit separately stated scoring condition.
  • Custom modules require distinct substantial work and README justification. Do not count the same custom feature as both major and minor. The two entries are placeholders; acceptance is evaluator-dependent.
  • All requirement summaries are paraphrases; the original PDF remains authoritative. Features named only in project examples are not extra catalog modules.
