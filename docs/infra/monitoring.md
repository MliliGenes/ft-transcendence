# Monitoring

Nook ships a local monitoring stack built on Grafana and Prometheus. It starts with the app (`docker compose up`); the services are defined in [`compose.monitoring.yaml`](../../compose.monitoring.yaml), which [`compose.yaml`](../../compose.yaml) includes.

Open **https://localhost/grafana/** and log in with the admin account from `envs/grafana.env`. Dashboards are in the **Nook** folder.

## What runs

| Container | Role | Reachable from |
|---|---|---|
| `grafana` | Dashboards, log search, alert view | Browser, only through Nginx at `/grafana/` with a login |
| `prometheus` | Stores metrics for 7 days and evaluates alert rules | Internal network only |
| `loki` | Stores container logs for 7 days | Internal network only |
| `alloy` | The collector: scrapes every metric source, ships logs, redacts secrets | Internal network only |
| `cadvisor` | CPU, memory, network and disk per container | Internal network only |
| `docker-socket-proxy` | Read-only Docker API for Alloy's log discovery; writes are denied | A private internal network shared only with Alloy |

How data flows:

```
cAdvisor, RabbitMQ (:15692), PostgreSQL exporters, health probes
        │  scraped every 15 s by Alloy
        ▼
     Alloy ──remote write──▶ Prometheus ──▶ Grafana
     Alloy ──container logs (redacted)──▶ Loki ──▶ Grafana
Prometheus alert rules ──▶ shown in Grafana
```

## Dashboards

| Dashboard | Shows |
|---|---|
| **Overview** | Up/down for the gateway, client, both services and MinIO; databases up; firing alerts; CPU and memory by service |
| **Containers** | Per-container CPU, memory, network, disk writes and restarts |
| **Databases & Broker** | PostgreSQL connections, transactions, size and deadlocks for `user-db` and `chat-db`; RabbitMQ connections, queue depth, unacknowledged messages and message rates |
| **Logs** | Searchable logs for every container, with a service filter and an error-rate graph |
| **HTTP & Realtime** | Probe availability, latency and status codes. Per-route HTTP and Socket.IO metrics come in phase B |

The dashboards are generated by [`infra/monitoring/grafana/build-dashboards.mjs`](../../infra/monitoring/grafana/build-dashboards.mjs). To change one, edit that script, run `node infra/monitoring/grafana/build-dashboards.mjs`, then `docker compose restart grafana`.

## Alert rules

Defined in [`infra/monitoring/prometheus/alerts.yml`](../../infra/monitoring/prometheus/alerts.yml) and visible in Grafana under **Alerting → Alert rules** and on the Overview dashboard.

| Alert | Fires when |
|---|---|
| `ServiceDown` | A health probe (gateway, client, user-service, chat-service, MinIO) fails for 1 minute |
| `ContainerRestarting` | A container restarts more than 3 times in 15 minutes |
| `ContainerHighMemory` | A container uses over 90% of its memory limit, or over 1 GiB without a limit, for 5 minutes |
| `PostgresDown` | A database is unreachable for 1 minute |
| `PostgresTooManyConnections` | A database uses over 80% of `max_connections` for 5 minutes |
| `RabbitMQQueueBacklog` | A queue has over 100 waiting messages for 5 minutes |
| `RabbitMQUnackedHigh` | A queue has over 50 unacknowledged messages for 5 minutes |

Alerts are not delivered anywhere (no email or chat). That is out of scope for a local stack.

To demo one: `docker compose stop chat-service`, wait about 90 seconds, and `ServiceDown` turns red. Then run `docker compose start chat-service`.

## Security and privacy

- **Only Grafana is exposed,** through the existing HTTPS gateway. Anonymous access, sign-up and organisation creation are off, and cookies are secure-only. Prometheus, Loki, Alloy and cAdvisor have no Nginx route and publish no ports.
- **Docker access is limited.** Alloy talks to Docker through `docker-socket-proxy`, which allows only reading containers, networks and events. The proxy sits on an internal network with no outside access. cAdvisor needs privileged, read-only access to the host to measure containers; it is not exposed anywhere.
- **The database login is read-only.** The `monitoring` PostgreSQL login has only the built-in `pg_monitor` role, which can read statistics but not application data.
- **Secrets are redacted before storage.** Alloy removes signed MinIO URL parameters, OAuth `code` and `state`, tokens in query strings, email-verification and password-reset tokens in paths, and bearer tokens or cookies. Message contents are never collected; the gateway logs only method, path and status.
- **Logs are size-limited.** Every container's Docker logs rotate at 10 MB × 3 files.

## Setup

1. Copy the two env templates and fill them in (both real files are ignored by Git):
   ```sh
   cp envs/grafana.env.example envs/grafana.env
   cp envs/monitoring.env.example envs/monitoring.env
   ```
2. `docker compose up -d --build`
3. **Existing databases only:** a new database creates the `monitoring` login automatically. If your `volumes/user-db` or `volumes/chat-db` already had data, create it once (no data is changed):
   ```sh
   docker compose exec user-db sh /docker-entrypoint-initdb.d/10-monitoring-role.sh
   docker compose exec chat-db sh /docker-entrypoint-initdb.d/10-monitoring-role.sh
   ```
   In Git Bash on Windows, prefix these with `MSYS_NO_PATHCONV=1` so the container path is not rewritten.

Monitoring data lives in the named Docker volumes `nook_grafana-data`, `nook_prometheus-data` and `nook_loki-data`. Named volumes avoid file-ownership problems with bind mounts on Linux hosts. `docker compose down` keeps them; `docker compose down -v` deletes them.

Grafana reads the admin credentials only on its first start. To change the password later, use Grafana's profile page, or remove the `nook_grafana-data` volume.

## Troubleshooting

| Symptom | Check |
|---|---|
| A dashboard says "No data" | Wait 30 seconds after startup. Then check `docker compose logs alloy` for `level=error` |
| PostgreSQL panels are empty | The `monitoring` login is missing or its password differs from `envs/monitoring.env`. Run the setup command in step 3 again |
| Container panels are empty | cAdvisor must be **0.54.0 or newer** when Docker uses the containerd image store (Docker Desktop and new Docker Engine 29 installs). Older versions only report the root cgroup |
| `/grafana/` returns 502 | Grafana is still starting. Check `docker compose ps grafana` |
| Alloy logs `403 Forbidden` from Docker | The socket proxy is missing a read permission. `CONTAINERS`, `NETWORKS` and `EVENTS` must be `1` |

## How this maps to module D02 (Prometheus and Grafana)

| Requirement | Where |
|---|---|
| Metric collection | Prometheus, fed by Alloy every 15 s |
| Exporters and integrations | cAdvisor; RabbitMQ Prometheus plugin; PostgreSQL and blackbox exporters embedded in Alloy |
| Custom dashboards | Five provisioned dashboards in the Nook folder |
| Alerting rules | Seven Prometheus rules in `alerts.yml` |
| Secure Grafana access | HTTPS through Nginx, required login, no anonymous access or sign-up, backends not exposed |

Logs (Loki) are an extra beyond D02. They are not the ELK stack, so they don't count toward D01.
